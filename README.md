# Baizixu · Personal Lab

[中文](README.zh.md) · [English](README.md)

Built with Astro + TypeScript + Markdown Content Collections, this site is made to maintain essays, projects, tools and bookmarks over the long term.

> Engineering rules, directory responsibilities, module conventions and the verification flow live in [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Local development

```bash
npm install
npm run dev
```

Then open the local address printed in the terminal. Common commands:

```bash
npm run check             # Astro type check
npm run check:structure   # fail if a source file exceeds 300 lines
npm run build             # structure check + type check + static build into dist/
npm run preview           # preview the build output
```

## Directory structure

- `src/content/entries/`: Chinese Markdown content for essays, ideas, projects, tools, games and bookmarks. Add a file and it appears on the site.
- `src/content/entriesEn/`: English translations matching the Chinese entry ids; falls back to Chinese when a translation is missing.
- `src/i18n/`: language dictionary (`ui.ts`) and path/translation helpers (`utils.ts`).
- `src/pages/`: routes for the homepage, article/project/game/idea lists, about page and detail pages; the English routes live in `src/pages/en/`.
- `src/components/sections/`: homepage content sections.
- `src/components/shared/`: cross-page components (footer, contact dialog).
- `src/components/pages/`: page components shared by the Chinese and English routes.
- `src/scripts/`: global interaction scripts (theme/dialog, site search, PWA install).
- `src/scripts/pages/`: tool/game scripts bound to a specific page.
- `src/styles/global.css`: global style entry, importing CSS modules in order.
- `src/styles/modules/`: CSS modules split into base, homepage sections, standalone tools, games, responsive overrides, global UI and theme skins; the numeric prefix is the import (cascade) order and every file stays under 300 lines.
- `src/data/themes.ts`: theme skin config (id / name / description). Adding a skin means one entry plus one skin module.
- `src/lib/`: browser utilities shared across features, e.g. defensive localStorage helpers.
- `scripts/check-file-limits.mjs`: source line-limit check run before the build.
- `public/assets/`: local logo, favicon, homepage illustrations and project covers.
- `scripts/generate_assets.py`: regenerate the whole set of site graphics with Pillow.

Files for games and tools:

- `src/pages/games/`: game list, game detail pages and the self-hosted human benchmark.
- `src/pages/tools/`: the Tiny Tools collection, the tools directory and standalone tool pages.
- `src/scripts/pages/tiny-tools.ts`: timestamp, Base64, MD5, color and JSON tool logic for Tiny Tools.
- `src/data/benchmark.ts`: test configuration for the human benchmark.
- `src/scripts/pages/benchmark.ts`: state, page control and scoring for the human benchmark.
- `src/scripts/pages/benchmark/`: benchmark implementations grouped by memory, speed and logic.
- `src/data/about.ts`: author intro, progress and changelog data in one place.
- `src/content/config.ts`: frontmatter fields and validation in one place.

## Languages and themes

- **Languages**: Chinese is the default with no URL prefix; English lives under `/en/`. UI copy is in `src/i18n/ui.ts`; components read it with `useTranslations(locale)` and build paths with `localizePath()`. Content translations live in `src/content/entriesEn/` and fall back to Chinese when missing.
- **Theme skins**: configured in `src/data/themes.ts`. Skins are the modules numbered 31 and up in `src/styles/modules/`, imported last, and only override colors, borders, shadows and type — never layout. The palette menu in the top bar switches them online and remembers the choice in `localStorage.bai-skin`.

## Graphics

Site graphics are generated by a local Python/Pillow script, with no online image service:

```bash
python3 scripts/generate_assets.py
```

Change colors or drawing logic in the script and re-run; output goes to `public/assets/`.

## Human benchmark

`/games/human-benchmark/` is a local rewrite built independently from a public reference project and now includes 18 tests. Scores are stored only in the browser localStorage, with no backend.

Reference project: <https://gitee.com/aring1998/human-benchmark>

The reference project uses GNU GPL v3. This implementation uses independent code and does not copy files from it; if you keep adapting or distributing the reference code, follow its license.

## Page conventions

- External links on detail pages must appear in the intro area: after the title, lede and cover, before the body, so readers do not have to scroll to find them.
- Action buttons on the same detail page go into `.detail-actions`, with the on-site experience first and external links after; buttons share a height and stay top-aligned.
- External links need a clearly different visual style (color, underline or an external icon) and open in a new tab.
- The homepage projects section uses a uniform grid and does not give the first project an extra column span or larger width; on mobile it drops to a single column.
- Online tools use `kind: tool`, entering the “more tools” collection via `area: tiny` or a standalone entry via `area: standalone`; prefer an on-site `demoUrl` and keep them out of the project archive.
- Based on the tool categories at baizixv.com, but every tool is implemented independently here; currently time, encoding, color, QR code and finance tools. Processing is local in the browser by default, with no upload or storage of input.
- `kind: media` is used for library entries, distinguishing books, screen, music and games via `mediaType: book | screen | music | game`, and may add creator/director, year, rating, book word count, `color` for a visual theme and an external link; book titles always use the Chinese title marks.
- Ogden 850 is an independently implemented English learning project; data lives in `public/data/ogden850.json` and progress and saved words stay in browser `localStorage`.

## Versioning

- The version has a single source: `version` in `package.json`. The About page reads it directly (`currentVersion`).
- The changelog lives in `src/data/about.ts` under `releases` (Chinese and English); its **first entry must match** `package.json`.
- `npm run check:version` verifies they match and is already part of `npm run build`, so a forgotten bump fails the build.
- To release: bump `package.json` and add a matching release entry at the top of `releases` in both languages.

## Deployment

- **Vercel**: import the repo, set Framework Preset to `Astro`, Build Command to `npm run build`, Output Directory to `dist`.
- **Alibaba Cloud CAP / Tencent Cloud Makers**: use a Node.js build environment, run `npm install && npm run build`, and publish the `dist` directory.
- Output is fully static; no backend service or database is required.

## Adding an article

Create a Markdown file in `src/content/entries/`, for example:

```md
---
kind: article
title: A new article
description: Summary shown in the homepage list.
date: 2025-03-20
minutes: 06 min
tag: Notes
color: blue
featured: false
---

Write the body here; the build generates a standalone detail page.
```
